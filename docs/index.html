[ 05 ] Process

How a
claim earns
its place.

The working loop is simple: define the claim, build something testable, look for failure, and leave a way for someone else to inspect the result.

01

State the claim

Write down exactly what will be true — and what won't. The boundary is part of the spec, not a disclaimer added later.

02

Build the harness

Tests, fixtures, frozen cohorts, pinned images. If it can't be measured, it doesn't ship as a claim.

03

Try to break it

Premortems, stress and chaos runs, adversarial payloads, tampered receipts. The tool gets turned on its own history.

04

Ship the receipt

Signed, hash-chained output and one command a stranger can run in about a minute — or a signed refusal when the evidence isn't there.
